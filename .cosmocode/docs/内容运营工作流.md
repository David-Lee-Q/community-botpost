# 内容运营工作流（Skill）

面向本项目的「发文 → 评价 → 报告」运营闭环操作指南。后续 Agent 接手运营任务时，按此工作流执行。

## 闭环总览

```
发布计划(plan.json) → runner 定时发布(publish.py)
        │
        ▼
台账数据(fetch_articles.py) ──→ 自动评价(auto_review.py)
        │                              │
        ▼                              ▼
台账前端(ledger/index.html)   每周综合评分(review_engine.py)
        │                              │
        ▼                              ▼
飞书日报/周报(report.py)    改进任务(quality_tasks.md) 反馈到新文章
```

## 1. 发文

- 文章正文 markdown 存 `bot-articles/article-N.md`，封面图按主题归档到 `bot/covers/<主题关键词>/`
- `bot/plan.json` 新增条目（time/title/category/file/summary/images/cover）
- 发布前核对 `.cosmocode/quality_tasks.md` 未完成改进项
- 规范红线：封面 800×400 ≤1MB；正文 ≥1000 字、每段 ≥200 字、≥2 张免费图；标题禁冒号；需 120 字摘要；正文不得重复标题/二级标题文字
- 配图：正文图从 magnific.com / Pexels / Unsplash / Pixabay 检索免费图并直接引用链接；封面图下载到工作区按主题分类保存，避免多篇混用

## 2. 评价

- 发布后 runner 自动执行 `fetch_articles.py`（刷新数据并触发 `auto_review.py`）
- 自动评价基于传播表现百分位（浏览 0.7 + 互动 0.3，区间 40-95），不覆盖人工评价
- 每周一 06:00 `review_engine.py` 计算上一完整周综合分：
  - 同步 `ledger/data/score_history.json`
  - 更新 `.cosmocode/quality_tasks.md`（幂等，可标记完成）
  - 更新 `.cosmocode/docs/质量改进记录.md` 与 MEMORY.md
- 周评分 < 85 时，下批文章发布前必须落实对应改进要点

## 3. 报告

- 每日 18:00 飞书每日总结（蓝色卡片）
- 每周一 10:00 飞书每周总结（绿色卡片）
- 卡片格式：interactive 卡片；文章表现用 `column_set` 表格（# / 标题[超链接] / 浏览-互动）；评分按 85/70 分档着色（绿/橙/红）
- Webhook 与脚本见 `bot/report.py`；`--preview` 仅打印不推送

## 4. 台账

- 展示页：`ledger/index.html`，静态服务器根路径即首页（`python3 -m http.server 8090 --bind 0.0.0.0`）
- 图表：发布量（日/周/月）、分类分布、分类趋势、评价分数趋势、浏览趋势、互动趋势（同比/环比）
- 台账数据源 `POST /api/member/article/1447?pageNum=N&pageSize=100`；分类映射 `GET /api/cate/list`

## 排错速查

| 现象 | 处理 |
|------|------|
| token 失效（401） | runner 通过 Playwright 自动重登 `bot/token.txt` |
| 分类名异常 | 重新拉取 `GET /api/cate/list` 更新映射（id→name，含 -1/-2） |
| 趋势图近期无数据 | 核实是否为真空期（平台确实未发文），非数据缺失 |
| 飞书推送失败 | 检查 `report.py` 的 `WEBHOOK` 与 `code==0` 返回值 |

## 完整文档

- 定时任务：`bot/SCHEDULE.md`
- 评价标准：`.cosmocode/docs/社区文章质量评价标准.md`
- 质量记录：`.cosmocode/docs/质量改进记录.md`、`.cosmocode/quality_tasks.md`
