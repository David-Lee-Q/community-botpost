# K8s安全别只扫镜像的4个硬指标

## 安全不是上线前的扫描

一次生产事故里，镜像扫描全部通过，集群却在10分钟内被拖走密钥。攻击者没有攻破入口，而是从一个低权限服务跳到内部元数据接口，再调用集群 API 创建特权容器，把日志、配置和凭据打包外传。这类事故反复说明，云原生环境的安全边界已经不在传统防火墙，而在身份、网络、运行时与供应链的持续验证。很多团队把安全理解为上线前的一次检查，但容器、服务网格和动态编排让攻击面不断变化，静态规则很快过期。真正有效的防线，不是把扫描报告做得更厚，而是把关键风险变成可度量的工程指标，让每次发布都能回答：谁有权访问、流量能去哪、异常如何被发现、组件从哪里来。这些指标也能用于事故复盘和合规审计。

## 身份最小权限是第一道闸

身份最小权限是第一道闸，因为它直接决定攻击者拿到一个服务后能走多远。在一次红队演练中，攻击者利用一个默认 ServiceAccount 的宽泛权限，读取了多个命名空间的 Secret，随后用窃取到的 token 调用 API 创建特权 Pod，整个过程只用了不到20分钟。云原生环境里，Pod 会频繁创建、销毁和迁移，传统基于 IP 和主机的信任模型很难跟上，身份才是更稳定的锚点。工程团队应把每个工作负载视为独立身份，为其分配独立 ServiceAccount，禁用匿名访问，并按资源、动作和命名空间收紧 RBAC；对跨服务调用使用短期凭证，避免把长期密钥写进镜像或配置。权限变更应像代码一样走评审，避免临时授权长期化。只有当身份权限可枚举、可审计、可回收时，安全才从口号变成可验证的控制。

## 微隔离让横向移动变贵

微隔离不是网络策略的摆设，而是把横向移动成本抬高到攻击者放弃的关键。某电商集群曾允许 Pod 默认互通，一次应用漏洞让攻击者扫描同网段，最终定位到数据库端口并触发批量数据导出；复盘发现，数据库并没有直接暴露公网，却被内部流量打穿。云原生网络由 CNI、Service 和 Ingress 动态组成，东西向流量比南北向更隐蔽，也更难被边界设备看见。生产集群应默认拒绝 Pod 间访问，再按服务标签放行必要路径，例如订单服务只能访问库存服务和数据库，管理面与业务面分离，调试端口单独隔离。策略漂移要纳入巡检，防止手工放行变成永久后门。网络策略还要和发布流程绑定，新增服务若没有策略就拒绝上线，让默认安全成为交付前提。

## 运行时检测补住漏洞管理的盲区

运行时检测补住漏洞管理的盲区，因为扫描器只能回答已知问题，无法回答攻击是否正在发生。某支付服务部署了最新镜像，但一个依赖库存在未知内存破坏，攻击者通过接口触发异常进程并执行外联命令，静态扫描和基线检查都没有覆盖这条路径。云原生运行时短生命周期、多租户和共享内核，使异常进程、文件写入和非授权外联成为高价值信号。团队应优先为核心服务接入进程、文件和网络事件采集，建立正常行为基线，对异常 exec、提权、敏感路径修改和未知域名外联设置告警；采集方式可用 eBPF、轻量探针或边车，但要控制日志成本，避免把可观测平台变成性能瓶颈。告警必须关联服务、版本和调用链，否则只是噪音。运行时检测的价值不在告警数量，而在把正在发生压缩到分钟级发现。

## 供应链与可观测决定安全上限

供应链与可观测决定安全上限，因为再好的运行时控制也挡不住一个被污染的组件。某团队引入 SBOM 和镜像签名后，漏洞修复周期从14天降到3天，准入控制也阻止了未签名镜像进入生产。云原生安全最终要形成闭环：身份定义权限，网络限制路径，运行时发现异常，供应链保证来源可信，可观测把信号变成响应动作。工程团队落地时不必追求一步到位，可以先从身份最小权限和默认网络拒绝开始，再逐步补齐运行时告警与 SBOM 跟踪。对关键业务，还应定期做权限滥用和横向移动演练。趋势上，安全会持续左移并嵌入 CI/CD，但真正的分水岭不是工具堆叠，而是能否把安全指标写进发布门禁、事故复盘和日常运维，让每次变更都带着可验证的信任上线。
