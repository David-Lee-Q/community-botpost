# API网关不是反向代理这4个坑我全踩过

去年大促前夜，一个订单查询接口的 P99 从 80ms 飙到 4.2 秒，值班同事排查到凌晨三点，最后发现业务代码一行没改——罪魁祸首是当天下午网关上加的一次重试配置。这个场景很典型：我们习惯把 API 网关当成会转发请求、顺便做点鉴权的反向代理，却忘了它握着整个系统的入口流量，一个默认值就能放大成全站故障。真正把网关用对，靠的不是把配置项背熟，而是理解它在链路中的位置——它是流量治理的指挥部，不是挡在业务前面的透明管道。这篇文章不讨论网关选型，只复盘我们在生产环境踩过的四类坑：超时与重试、鉴权边界、灰度路由、限流与观测，以及最后沉淀下来的那套配置基线。

## 坑一 超时重试没算总账 一次点击变成十二次调用

网关最危险的配置方式，是给所有下游接口套用同一套全局超时和重试策略。我们最早的配置是全局读超时 60 秒、失败重试 3 次，而客户端 SDK 自己还带 2 次重试，两层一乘，一次用户点击在最坏情况下会变成 12 次下游调用。那次故障里，库存服务的连接池 200 个连接在 40 秒内被占满，后续请求全部排队，健康检查超时，实例被逐个摘除，雪崩就是这么来的。后来我们把超时改成按路由分组配置：下游接口自报 P99 耗时，网关取 1.2 倍作为读超时，同时把最外层超时预算卡在 3 秒以内，保证整条链路有明确上限。重试只对幂等的 GET 放开，次数不超过 1 次，并且必须带指数退避和随机抖动，避免实例重启瞬间的重试洪峰同时砸向下游。改完后同样的故障注入演练中，下游峰值调用量从 12 倍降到 3 倍，没有出现级联超时。

## 坑二 细粒度鉴权塞进网关 延迟和风险一起涨

网关做认证、业务做授权，这条边界一旦模糊，性能和安全隐患会同时出现。我们曾经为了“统一收口”，把整个 RBAC 权限表下发到网关，规则文件涨到 8MB，每次请求都要在内存里做一次线性匹配，网关实例 CPU 从 15% 涨到 70%，单请求凭空多出 12 到 18 毫秒。更麻烦的是安全边界被抹平了：网关一旦被绕过，下游接口因为不再校验身份，等于全部裸奔。后来我们把职责拆开，网关只做三件事——校验 JWT 签名与过期时间、提取租户和角色标识、做接口级粗粒度黑白名单；资源级的细粒度判断回到业务侧，用本地缓存加短 TTL 兜底。内部调用也不再直接透传外部 token，而是在网关做一次 token 交换，下游只认内部凭证。改完网关 P99 回落约 9 毫秒，权限变更的发布链路也从“全网关灰度”变成业务服务自己热更新。

## 坑三 灰度路由被一个 header 大小写毁掉

路由和灰度看起来最没技术含量，出起问题来却最隐蔽。我们做新版本灰度时，按 X-Channel 请求头把 5% 的流量切到新服务，灰度跑了两个小时没人发现异常，直到数据组反馈新版本订单量占比是 100%。原因简单到可笑：不同客户端发出的 header 有大写也有小写，网关匹配规则区分大小写，未命中的流量走了默认路由，而默认路由被运维改成了新版本。同类问题还有 URL 末尾斜杠、路径大小写、query 参数顺序，任何一个差异都可能让请求落到兜底服务上。经验是三条：匹配前统一做 header 名称归一化；兜底路由必须显式指向稳定版本，而不是“最后配置的那个”；灰度规则必须绑定监控和自动回滚，我们现在的阈值是 1 分钟内错误率超过 1%、或 P99 超过基线 50%，网关自动摘除灰度标签。灰度不是把一个标签打上去，而是给流量准备一条随时能退回去的路。

## 坑四 限流算法选错 毛刺会教你做人

固定窗口计数器实现最简单，也最容易在窗口边界放行双倍流量。我们早期用单机固定窗口限流，单实例设计值 1000 QPS，但在窗口切换的临界点，相邻两个窗口各放行一批，实测瞬时峰值冲到 1900 以上，下游数据库在 30 秒内连接数打满。修复思路是网关侧改成集中式滑动窗口，同时在每个实例保留一小份本地配额做兜底，这样即使集中存储抖动，也不至于完全失守。改完峰值被压在 1050 左右，误杀率从 3% 降到 0.2%。限流维度也不能只按接口，必须带上租户和调用方，否则一次异常调用就能把整个接口的配额吃光。最后是可观测性：网关指标至少要覆盖路由级 QPS、P99、上游连接数、限流拒绝数和重试次数，日志按调用方采样、长尾请求全量保留，否则出事时你只能看到一条平均线，看不到那个真正拖垮系统的尖峰。

回头看不难发现，这四个坑的共同点是把网关当成配置项，而不是系统组件：超时要有预算、鉴权要有边界、路由要有退路、限流要有全局视角。如果你正准备接网关，建议先做三件事：把下游接口的 P99 拉出来，按路由重算一遍超时和重试预算；把网关职责清单缩到认证、路由、限流、观测四件事，其余交给业务；给每条灰度规则配一条自动回滚条件。至于配置基线，其实就那么几行——按路由的超时、只让幂等请求重试、header 先归一化、兜底指向稳定版本、全局限流加本地兜底。网关的价值不在于功能有多全，而在于它出事的时候，你能不能在两分钟内把它变回那个什么都没做过的透明管道。
