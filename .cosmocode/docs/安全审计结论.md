# 安全审计结论

- 审计日期：2026-08-08
- 审计对象：社区自动发文 bot（/workspace/bot）+ 发布台账展示（/workspace/ledger）
- 审计方式：代码静态审查 + 运行环境检查 + 只读接口探测（未执行任何攻击性测试）
- 审计范围文件：publish.py、runner.py、fetch_detail_urls.py、fetch_articles.py、index.html、token.txt、plan.json、HEARTBEAT.md

## 一、总体结论

未发现高危漏洞。系统整体安全风险可控，认证机制有效，无注入与 XSS 风险面。存在 2 项中等级别凭据管理问题与 2 项低风险问题，修复成本低，建议按本文档整改。

## 二、问题清单

### 发现 1（中）：账号密码硬编码于源码

- 位置：`/workspace/bot/publish.py:33-34`
- 现象：社区账号 `15854240615` 与密码以明文形式直接写死在 `refresh_token()` 中
- 风险：源码一旦进入版本库或泄露，凭据立即暴露，可被用于冒充账号操作
- 建议：
  - 将凭据移入 `~/.config` 或 `.env` 文件，权限设为 600
  - 运行时通过环境变量读取，源码不落凭据
  - 提交代码前用 `.gitignore` 排除凭据文件

### 发现 2（中）：token 文件权限过宽（已修复）

- 位置：`/workspace/bot/token.txt`
- 现象：JWT 令牌文件初始权限为 644，任意本机用户可读
- 风险：JWT 有效期内可被复制用于调用平台写接口
- 处置：已执行 `chmod 600`，当前权限为 `-rw-------`，风险已消除

### 发现 3（低）：plan.json 含绝对路径

- 位置：`/workspace/bot/plan.json` 的 file / cover 字段
- 现象：文章正文与封面使用 `/workspace/bot/...` 绝对路径
- 风险：迁移到其他目录时路径失效，需手工修正
- 建议：改用相对 BOT_DIR 的相对路径

### 发现 4（低）：台账全量数据随预览公网暴露

- 位置：`/workspace/ledger/data/articles.json`（689 篇，约 186KB）
- 现象：台账页面为静态站点，全量文章元数据（含浏览/评论/点赞数）可通过预览地址公网读取
- 风险：信息泄露面取决于预览地址的传播范围
- 建议：如数据含不宜公开字段，可在 fetch_articles.py 中裁剪字段后再导出

## 三、通过项（无风险）

| 检查项 | 结论 | 依据 |
|--------|------|------|
| 认证机制 | 通过 | 所有写操作均携带 `s-user-token` header；JWT 有效期约 7 天，失效自动重登 |
| 注入风险 | 通过 | 全部走 HTTPS + requests 参数化调用，无 SQL/命令拼接面；`title_exists` 采用标题精确匹配 |
| 前端 XSS | 通过 | 台账页对所有用户可控字段（标题、分类、时间）统一经 `escapeHtml` 转义后再注入 DOM |
| 凭据日志泄漏 | 通过 | 登录脚本仅输出 `TOKEN:` 前缀，不打印账号密码；密码明文仅存在于内存变量 |
| 网络行为 | 通过 | 仅访问 openlab.cosmoplat.com 与 iam.cosmoplat.com 官方域，无隧道、无代理、无第三方回连 |
| 第三方组件 | 通过 | 仅 Playwright + requests + Chart.js（CDN），无第三方 Agent、无可执行下载脚本 |
| 异常退出 | 通过 | runner 对 publish/fetch 子进程均有超时与错误捕获，失败不影响主循环 |
| 数据一致性 | 通过 | 详情 URL 以 bot 返回的 article_id 为准，列表点击仅作校验，防同名重复文章误记 |

## 四、整改建议汇总

1. 凭据外置：账号密码迁移至权限 600 的配置/环境变量文件，源码去硬编码（对应发现 1）
2. 项目纳入版本控制：当前仓库无任何 commit，建议初始化 git 提交，并在 `.gitignore` 排除 `token.txt`、`login_state.json`、`data/articles.json` 等敏感或派生文件
3. plan.json 路径改相对路径（对应发现 3）
4. 台账数据按需裁剪敏感字段（对应发现 4）
